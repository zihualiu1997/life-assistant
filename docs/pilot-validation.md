## 固定 OpenClaw 的实际集成验证

新增 `tests/container_gateway_config.py`：在断开外网、只读根目录、2GiB 内存的临时容器内，启动真实 OpenClaw 2026.9.5、实际产品中转与虚构上游。微信轮询关闭，不使用真实账号。该检查已纳入 Linux CI。

实际发现并修复了 Windows 构建文件权限导致插件被拒、私有中转被网络保护拦截、默认 memory-core 自行启用后台整理，以及 OpenClaw 自动移动人设文件造成后续投影位置不一致的问题。仅对固定内部模型地址启用私网访问；托管模式禁用内置记忆插件并固定独立 agentDir，产品根 SOUL.md 仍是主要来源。

网关普通接口经实际流式上游返回回答，用量成功归属于虚构实例。原生微信消息以接收钩子的已绑定本人、原始消息 ID、运行 ID 和会话 ID 建立来源；单元测试验证跨人、跨会话和冲突重放不能写入。图片等未分类媒体不会自动升级为已确认事实；捕获接口保留来源类别和原生消息标识，重放不能改写来源。

实际进一步发现：固定版本的 `message_received` 事件没有填入类型声明中可选的运行 ID。因此补丁 v2 在微信 SDK 完成授权后、派发模型前，使用 SDK 自己生成的 UUID 建立原生消息与会话绑定，并把同一 UUID 明确传入回复运行参数。绑定文件仅存在本人私有状态目录，权限 0600、有数量和时效限制；完成捕获后清除，不从 prompt 或会话名称推断身份。

候选镜像 `bc9ef19a3e75b144adfdd60816390337e3965e9a7d03315a340d4d2875bb1bd8` 已通过实际网关正向落盘检查：临时测试插件为虚构 CLI 运行调用真实 SDK 的来源绑定函数，真实产品桥接随后写入日记并把回复关联到原始消息。测试还确认即使会话名为 `agent:main:main`，已授权来源也不会因名称不含 weixin 而漏记。Node 测试另行验证实际 SDK 处理模块传递相同运行 ID。基础 Python／Node 镜像也已按已验证摘要锁定，避免相同标签发生漂移。

**边界：旧版 HTTP Chat Completions 入口没有提供原生接收身份，测试确认它不能靠 prompt 或历史内容制造日记。正向检查使用虚构来源绑定及真实网关，没有连接微信平台，也没有完成微信传输到回复的整条链路；仍须真实账号验收。**

## 实际网页入口检查

2026-10-07，固定 Caddy 2.11.7 和 cloudflared 2026.10.0（摘要见 `deploy/ingress-images.json`），在 Debian 的封闭 Docker 网络中运行 `scripts/pilot-ingress-check.py`。测试使用五份虚构账号和无效的假 Tunnel token，不连接 Cloudflare 或供应商。

实际发现并修复三处主机生成配置的问题：Caddy 官方二进制带 NET_BIND_SERVICE 文件能力，原 cap_drop ALL 会阻止执行；cloudflared 默认 UID 65532 无法读取 root 所有的 0600 凭据；Caddy 默认指令排序会先执行用户转发再执行单独的私有路径 respond。现在 Caddy 仅补回所需能力并禁止提权，cloudflared 以 UID 0 读取唯一的私有秘密挂载且丢弃全部能力，路径拦截置于保持执行顺序的 route 内。

重跑通过：五个主机名正确路由，未登录无法导出，Cookie 带 __Host 前缀且 Secure/HttpOnly/SameSite=Strict、无 Domain 属性；其他人的 Cookie 被拒绝；缺 CSRF 或跨来源的写入被拒绝；导出不串人且响应 no-store；普通及编码后的内部路径均返回 404；未知主机名返回 404；0600 Tunnel 文件成功读取后被识别为无效测试 token。报告为 `.test-artifacts/ingress-check.json`。51 项 Python 回归通过；实际入口步骤已加入 CI 定义，但远程 CI 本轮未运行。
